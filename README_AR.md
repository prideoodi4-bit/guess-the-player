# بوت احزر اللاعب والنادي ⚽

الملف يحتوي البوت وقاعدة البيانات بالفعل: **700 لاعب، 110 أندية، 3361 تلميحاً**: 3240 تلميحاً أصلياً و121 تلميحاً جديداً عن انتقالات وبطولات وأحداث 2024–2026.
لا تحتاج توليد بيانات أو شراء API للأسئلة. تحتاج توكن بوت من BotFather واتصالاً بتيليغرام.

## تشغيل سريع على Windows

1. فك ضغط الملف في مجلد مستقل.
2. ثبّت Python 3.11 أو أحدث، واختر Add Python to PATH.
3. انسخ `.env.example` وسمِّ النسخة `.env`.
4. افتح `.env` واكتب توكنك بدل `PUT_YOUR_BOT_TOKEN_HERE`.
5. اضغط `run.bat`. أول مرة يثبّت المكتبات، ثم يبدأ البوت.
6. أضف البوت للكروب، وافتح القسم المطلوب واكتب `/game`.

لا ترسل توكنك داخل الكروب. ما موجود أي توكن حقيقي في هذا الملف.

## تشغيل على استضافة أو Linux

المطلوب خدمة Python تعمل باستمرار، وليست صفحة ويب أو وظيفة تتوقف بعد ثوانٍ.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# افتح .env وضع BOT_TOKEN
python bot.py
```

أو عبر Docker:

```bash
cp .env.example .env
# ضع التوكن في .env
docker compose up -d --build
```

البوت يستخدم polling؛ ما يحتاج رابط webhook أو منفذ HTTP. شغّل **نسخة واحدة فقط** لكل توكن.
على استضافتك استخدم `pip install -r requirements.txt` كأمر تثبيت و`python bot.py` كأمر بدء.
إذا استضافتك تمسح الملفات عند إعادة التشغيل، اربط مجلداً دائماً وحدد `DATABASE_PATH` عليه.

## إعداد الكروب — حتى يشوف البوت الأجوبة

من BotFather:

1. `/setprivacy`
2. اختر بوتك.
3. اختر Disable.
4. إذا كان البوت مضافاً من قبل، احذفه وأعد إضافته حتى يُطبَّق الإعداد.

يمكن للبوت المشرف استقبال رسائل الكروب أيضاً. تأكد من السماح له بإرسال الرسائل.
إطفاء privacy يسمح للبوت بقراءة أجوبة اللاعبين العادية. إذا بقي مفعّلاً قد لا تصله الأسماء المكتوبة بالكروب.

## أقسام الكروب (Topics)

افتح القسم الذي تريد اللعب داخله واكتب `/game`. تبقى الأسئلة والمؤقتات والأجوبة والنتائج داخل نفس القسم.
لكل قسم لعبة ونقاط وسجل أسئلة مستقل؛ يمكن اللعب في عدة أقسام بنفس الوقت.
أوامر `/score` و`/top` و`/remaining` و`/stop` و`/reset` تخص القسم الذي كتبتها داخله.
إذا أُغلق القسم أو حُذف، لا يحوّل البوت الرسائل إلى القسم الرئيسي. اسمح للبوت بالإرسال في الأقسام المطلوبة.
الكروب العادي يعمل أيضاً. قسم General يحافظ على سجل الكروب القديم عند الترقية.

## طريقة اللعب

1. اكتب `/game`، واختار اللاعبين أو الأندية.
2. اختار 5، 10، 15، 20 جولة، أو اكتب `/rounds 12` لأي عدد موجب ضمن الأسئلة المتبقية.
3. المشاركون يضغطون «انضمام» أو يكتبون `/join`.
4. صاحب اللعبة أو أدمن الكروب يضغط «ابدأ» أو يكتب `/begin`.
5. اكتب الجواب برسالة مستقلة: اسم اللاعب أو النادي فقط. الانضمام متاح أثناء اللعبة.

صيغة مختصرة: `/game players 10` أو `/game clubs 8`، ثم `/join` و`/begin`.

كل جولة لها أربعة تلميحات؛ كل تلميح يبقى 20 ثانية. أول جواب صحيح يحسم الجولة:

| التلميح | النقاط |
|---|---:|
| الأول | 40 |
| الثاني | 30 |
| الثالث | 20 |
| الرابع | 10 |

إذا انتهت 80 ثانية بلا جواب، يعرض البوت الاسم ويبدأ الجولة التالية.
ماكو خصم على الجواب الخطأ. النصوص المعدَّلة ما تنحسب؛ اكتب جواباً جديداً.
لكل لاعب أسماء عربية بديلة، وكذلك أسماء إنكليزية. يتجاهل البوت اختلاف الحروف الكبيرة والتشكيل وعلامات الترقيم.
إذا اسم العائلة مشترك، اكتب الاسم الكامل. مثلاً «رافينيا ألكانتارا» يختلف عن «رافينيا دياز».

## العشوائية ومنع التكرار

كل سؤال يُسحب عشوائياً من الأسئلة التي **لم تظهر في هذا القسم**.
يُحفظ استخدامه عند سحبه، حتى إذا توقف البوت أثناء الجولة.
منع التكرار مستمر بين الألعاب وبعد إعادة التشغيل. لكل كروب وقسم ونوع أسئلة سجل مستقل.
بعد استهلاك البنك، يتوقف البوت عن إعطاء أسئلة لهذا النوع؛ لا يعيدها من نفسه.
الأدمن يستطيع إعادة إتاحتها فقط بـ`/reset` ثم الضغط على تأكيد. النقاط لا تُمسح.

اللعبة الجارية نفسها لا تستأنف بعد إعادة التشغيل. عند انقطاع مفاجئ يعلن البوت أن اللعبة توقفت؛
ابدأ لعبة جديدة. مجموع النقاط والأسئلة المستعملة يبقى محفوظاً.

## ترقية النسخة القديمة

1. أوقف البوت القديم وخذ نسخة من مجلد `state` وملف `.env`.
2. استبدل ملفات الكود والبيانات بالملفات الجديدة، واحتفظ بمجلد `state` وملف `.env` الخاصين بك.
3. ثبّت المكتبات من `requirements.txt` ثم شغّل البوت.

تترقّى قاعدة البيانات تلقائياً. النقاط والأسئلة المستعملة القديمة تنتقل إلى قسم General؛
الأقسام الأخرى تبدأ بسجلات مستقلة. اللعبة التي كانت جارية تحتاج بدءاً جديداً.
إذا تريد الرجوع للنسخة القديمة، استخدم نسخة قاعدة البيانات التي أخذتها قبل الترقية.

## نقل الاستضافة والنسخة الاحتياطية

كل ملفات الكود والبيانات ضمن هذا المجلد. معلومات الكروبات والنقاط في `state/game.sqlite3`.

- ضع رقم حسابك الرقمي في `OWNER_IDS` بملف `.env`.
- أرسل `/backup` للبوت **بالخاص**. يرسل نسخة SQLite كاملة وآمنة تشمل آخر النقاط المحفوظة.
- لنقل الاستضافة: أوقف النسخة القديمة، انقل ملفات المشروع، وضع النسخة الاحتياطية باسم
  `state/game.sqlite3` بالاستضافة الجديدة، ثم شغّل البوت هناك بالتوكن نفسه.
- إذا تنسخ الملفات يدوياً، أوقف البوت أولاً وانقل **مجلد state كاملاً**؛
  لا تنسخ ملف SQLite منفرداً بينما البوت يعمل، لأن بيانات حديثة قد تكون في ملف WAL.

الملف الذي حمّلته هنا لا يحتوي نتائج ألعابك المستقبلية؛ هذه تنشأ أثناء التشغيل.

## محتوى الأسئلة ومصدر البيانات

البنك يضم أسماء من حقبة 2010–2026، منها نجوم تاريخيون ونجوم أحدث مثل يامال وبالمر وماينو وإندريك.
أضيفت **121 تلميحاً موثقاً**: 56 عن 2026، و42 عن 2025، و23 عن 2024، تشمل 64 لاعباً و16 نادياً.
تاريخ مراجعة المصادر: 1 أكتوبر 2026. التحديث يخص هذه الإضافات؛ لا يعني تحديث انتقالات جميع اللاعبين الـ700.

البوت يحتفظ بالنصوص الأصلية كلها. عند ظهور سؤال لديه إضافات، يخلط تلميحاً إلى ثلاثة تلميحات جديدة
مع القديمة حسب درجة الصعوبة، ويترك تلميحاً أصلياً واحداً على الأقل. تبقى الجولة أربعة تلميحات من الأصعب إلى الأسهل.
يحاول السحب اختيار سؤال لديه إضافات بنسبة 50% عندما توجد أسئلة متاحة من هذا النوع؛
لا يعيد سؤالاً مستعملاً. يمكن تعديل النسبة عبر `RECENT_QUESTION_SHARE` بين 0 و1.
هذا توزيع عشوائي وليس وعداً بأن نصف كل لعبة سيكون حديثاً. لا يتحدث البنك تلقائياً بعد تاريخ المراجعة.

- 76 لاعباً لديهم تلميحات مكتوبة عن الأندية السابقة والبطولات والأحداث المعروفة في مسيرتهم.
- 624 لاعباً لديهم تلميحات متدرجة مبنية على سنة الميلاد والطول والقدم والمركز والجنسية،
  ثم النادي ورقم القميص **في بيانات موسم 2021–2022**.
- كل تلميح نادي مأخوذ من هذه اللقطة مكتوب معه الموسم، حتى لا يُفهم على أنه النادي الحالي.
- أسئلة الأندية مبنية على جذور التأسيس والألوان والمدينة والبلد والملعب التاريخي والمنافسين.
  الملعب قد يكون سابقاً أو مشتركاً، والمنافس المذكور ليس بالضرورة المنافس الوحيد أو الديربي المحلي.
- صعوبة التلميحات تقديرية؛ معرفة كل لاعب تختلف بين المشاركين. الأسئلة ليست كلها ألغاز إنجازات مخصصة.
- بيانات المراكز والطول قد تختلف قليلاً عن قوائم رسمية أخرى. المصدر الأساسي للجزء الأكبر بيانات FIFA 22 المبنية على SoFIFA.

انظر `SOURCES.md` و`data/manifest.json` للتفاصيل، و`data/modern_clues.csv` لمراجعة كل تلميح جديد وسنته ورابط مصدره.
هذا الإصدار يعمل من ملفات محلية؛ ما يتصل بأي موقع معلومات رياضية أثناء اللعب.

## تعديل الأسئلة

الملفات المستخدمة فعلياً: `data/players.json` و`data/clubs.json`.
لكل عنصر: `id` ثابت، `answer`، `aliases`، و`clues` من أربعة نصوص.
الإضافات داخل `extra_clues` وتتضمن `text` و`difficulty` من 1 إلى 4 و`event_year` و`source_url`.
توجد نسخ CSV لسهولة المراجعة في Excel؛ تعديل CSV وحده لا يغيّر أسئلة البوت.
بعد تعديل JSON أعد تشغيل البوت. لا تغيّر IDs القديمة حتى يبقى منع التكرار صحيحاً.

اختبار دون توكن:

```bash
python -m unittest discover -s tests -v
```

تم فحص تعداد البيانات، تكرار الهوية، الأسماء البديلة، استمرار الحفظ، استهلاك البنك،
التنافس على الجواب والمؤقتات، فصل الأقسام، ترقية قاعدة البيانات وخلط التلميحات بمحاكاة محلية. نجح 13 اختباراً. الاتصال الحقيقي بتيليغرام يحتاج توكنك، ولم يُختبر بهذا التسليم.
