# 🩺 Guess the Diagnosis — بوت احزر التشخيص

نسخة جاهزة للتشغيل ببنك 700 كيس أساسي: 186 Medicine، 251 Surgery، 145 Obstetrics & Gynaecology، و118 Pediatrics.

لكل كيس ثلاث طرق لعرض التلميحات: Easy وMedium وHard. المجموع 2100 طريقة عرض؛ **هذه ليست 2100 حالة مرضى مستقلة**. المستوى يغيّر كمية المعلومات المكشوفة بالبداية، وليس انتشار المرض.

## التشغيل السريع

1. فك ضغط الملف. ارفع **محتويات مجلد diagnosis_bot** إلى GitHub أو انقل المجلد كله مع المحافظة على مسارات الملفات.
2. أنشئ بوت من `@BotFather` بالأمر `/newbot` وخذ التوكن. لا تنشره في GitHub أو ترسله بالكروب.
3. تحتاج Python 3.11 أو أحدث. البوت يعمل بالمكتبة القياسية فقط، ولا يحتاج API مدفوعًا أو مفتاح OpenAI.
4. عيّن variable باسم `BOT_TOKEN` في الاستضافة. أو انسخ `.env.example` إلى `.env` وضع التوكن داخلها محليًا.
5. أمر التشغيل، من داخل المجلد:

```bash
python bot.py
```

على Windows إذا كان الأمر python غير متوفر استعمل `py bot.py`.

## Variables

| Variable | مطلوب؟ | القيمة |
|---|---|---|
| `BOT_TOKEN` | نعم | توكن البوت من BotFather |
| `CLUE_SECONDS` | اختياري | وقت كل تلميح بالثواني؛ افتراضيًا `25`، مثلًا `40` |
| `DB_PATH` | اختياري | مسار ملف SQLite على قرص دائم، مثل `/data/game.sqlite3` |

القيمة الافتراضية لـDB_PATH هي `state/game.sqlite3` داخل مجلد البوت. لا تحتاج CHAT_ID أو GROUP_ID أو THREAD_ID؛ البوت يأخذها من مكان بدء اللعبة.

**الاستضافة:** شغله كـWorker/عملية Python مستمرة، وليس صفحة static أو job ينتهي سريعًا. شغّل نسخة polling واحدة لكل توكن. لا يحتاج البوت HTTP port أو webhook. يحذف webhook القديم لنفس التوكن عند بدء polling، لذلك استعمل توكن مخصصًا له.

## تشغيل Docker اختياري

انسخ `.env.example` إلى `.env` وضع BOT_TOKEN، ثم:

```bash
docker compose up -d --build
```

ملف compose يربط النقاط وحالة الألعاب بمجلد `state` المحلي. عند استخدام منصة استضافة أخرى اربط قرصًا دائمًا واجعل DB_PATH يشير إليه؛ قرص الاستضافة المؤقت لا يحفظ البيانات بعد إعادة النشر.

## اللعب في الكروب وأقسامه

- أضف البوت للكروب مع صلاحية إرسال الرسائل. لا يلزم أن يكون أدمن حتى يرسل في الموضوع إذا كانت الصلاحيات تسمح.
- افتح القسم المطلوب داخل الكروب واكتب `/newgame` **هناك**. كل تلميح وكشف جواب ونقاط يبقى بنفس الموضوع.
- القسم الرئيسي له لعبة مستقلة؛ مواضيع الكروب الأخرى لها ألعاب مستقلة أيضًا.
- اختار الاختصاص ثم المستوى ثم الجولات: 5 / 10 / 15 / 20 أو عدد مخصص من 1 إلى 50.
- الجميع يگدر يجاوب؛ لا يحتاج join. صاحب اللعبة وحده يختار إعدادات بدايتها.
- اكتب اسم تشخيص واحد بالإنكليزي. أول جواب صحيح ينهي الكيس ويحسب نقاطه.
- لاستقبال الأجوبة العادية بالكروب، من BotFather: `/setprivacy` → البوت → `Disable`. إذا بقيت المشكلة، أزل البوت وأضفه مرة ثانية لتطبيق الإعداد حسب تيليگرام.
- إذا تريد إبقاء Privacy Mode مفعّل، الجواب بالأمر `/guess PE` يعمل بدل الرسالة العادية. عند وجود أكثر من بوت يمكن كتابة `/guess@YourBotName PE`.
- لا يقبل تعديل رسالة قديمة كجواب جديد ولا يقرأ رسائل بوتات أخرى.

## قبول الأجوبة

- `PE` و`Pulmonary embolism` و`Pulmonary thromboembolism` أمثلة لأسماء جواب واحد.
- الأحرف الكبيرة والصغيرة، الشرطة، المسافات، وبعض الفروق الكتابية لا تؤثر.
- يقبل حذفًا أو إضافة أو استبدال حرف واحد أو تبديل حرفين متجاورين في الاسم الطويل، إذا لم يلتبس بتشخيص آخر.
- الاختصارات والأسماء القصيرة تتطلب كتابة صحيحة. لا يقبل تشخيصًا آخر على أنه خطأ إملائي.
- لا يقبل قائمة احتمالات أو جملة مثل `PE or pneumonia`؛ اكتب اسم تشخيص واحد فقط.
- الأسماء البديلة موجودة في `aliases` داخل `data/cases.json` ويمكن توسيعها.

## العشوائية وحفظ التقدم

يحفظ البوت التشخيصات المعروضة والنقاط في SQLite حسب الكروب والموضوع. يبدأ بالتشخيصات التي لم تظهر بعد، ولا يكرر التشخيص داخل الكيم نفسه. إذا انتهى البنك المتاح يبدأ دورة جديدة. تغيير الصعوبة لا يعيد التشخيصات المحفوظة إلى البداية.

عند إعادة تشغيل البوت يرجع للكيس الجاري ويرسل تلميحه الحالي مرة أخرى مع نافذة 25 ثانية جديدة. النقاط محفوظة. لا يعوّض كل التلميحات الفائتة دفعة واحدة. القوائم التي لم يبدأ أصحابها اللعبة تحتاج `/newgame` جديدًا.

## النسخ الاحتياطي ونقل الاستضافة

من داخل المجلد:

```bash
python backup.py --output backup.sqlite3
```

الأداة تعمل backup صحيحًا لقاعدة SQLite، حتى أثناء تشغيل البوت. لتنقل الاستضافة: أوقف النسخة القديمة، انقل كود البوت وملف backup إلى الاستضافة الجديدة، عيّن BOT_TOKEN نفسه وDB_PATH إلى ملف القاعدة المنقول، ثم شغّل نسخة واحدة. لا تعتمد على GitHub لحفظ النقاط المتغيرة ولا ترفع قاعدة بيانات المشاركين إلى مستودع عام.

## توسيع بنك الكيسات

الملفات `data/medicine.txt` و`surgery.txt` و`obgyn.txt` و`pediatrics.txt` هي المصادر القابلة للتعديل. كل سطر:

```text
Section|Diagnosis|Alias 1;Alias 2|Fact 1|Fact 2|Fact 3|Fact 4|Fact 5|Fact 6
```

لا تضع رمز `|` داخل أي حقل. اكتب الحقائق من الأقل تحديدًا إلى الأكثر تحديدًا. كل الحقائق تخص نفس الحالة. لا تضع اسم الجواب صريحًا في التلميحات الأولى. ثم نفّذ:

```bash
python build_bank.py
python -m unittest discover -s tests -v
```

احتفظ بمعرفات الكيسات مستقرة: تعديل السطر يحافظ على معرفه، لكن إدخال أسطر في وسط المصدر قد يغيّر المعرفات. أوقف الألعاب الحالية قبل إعادة بناء البنك بعد تغيير ترتيب السطور.

## المحتوى والتغطية

الأمراض والفراكجرات والمضاعفات مرتبة حسب عناوين موقع البلوبرنت. تشمل العناوين الواسعة اختيارات تعليمية من الأمراض التي تدخل ضمنها، ولا يمثل البنك نسخة وزارية رسمية معتمدة أو حصرًا لكل مرض ممكن. بعض البنود ليست تشخيصًا، مثل anatomy والـprocedures وvaccination schedule، لذلك لا تتحول إلى أسئلة احزر المرض.

Radiology يظهر ضمن تلميحات التصوير والفراكجرات. Immunization ممثل بمضاعفة حساسية بعد اللقاح، وGrowth & Development ممثل بكيس developmental delay؛ هذان ليسا بديلًا عن مراجعة الجداول والمراحل نفسها.

الكيسات مؤلفة للتعلّم من الأنماط السريرية، ولم تخضع لمراجعة مستقلة من طبيب اختصاصي. بعض التشخيصات تظل assessment-based حتى لو وضحنا تلميحًا موجّهًا، ولا يُستخدم البوت لتشخيص مرضى حقيقيين. درجات Easy/Medium/Hard هي مقدار الكشف في اللعبة؛ ليست تقييمًا معتمدًا لصعوبة الامتحان.

تمت إضافة 300 كيس مع الحفاظ على الكيسات الأصلية ومعرفاتها. راجع `BLUEPRINT_AUDIT.md` لمطابقة 318 بندًا ضمن 46 فرعًا، وحدود تغطية كل بند.

راجع `BANK_INVENTORY.md` للقائمة الكاملة، و`SOURCES.md` للمصادر وحدود التحقق.

## تغيير وقت التلميح من Railway

استبدل `bot.py` بالنسخة المحدثة، ثم Variables → New Variable. الاسم `CLUE_SECONDS` والقيمة مثلًا `40` أو `60`. أعد نشر البوت لتطبيق القيمة. يقبل عددًا صحيحًا موجبًا فقط.

كل تلميح، بما فيه الأخير، يأخذ هذه المدة. عند القيمة 40 تظهر التلميحات عند 0، 40، 80، 120 ثانية، ويُكشف الجواب عند 160 ثانية إذا لم يُحزر. جداول 25 ثانية أعلاه تمثل الإعداد الافتراضي. الانتظار بين الكيسات يبقى 5 ثوانٍ.

## إعدادات الوقت من داخل Telegram — v4

اكتب `/settings` بنفس الكروب أو القسم، ثم اختار الوقت من الأزرار. يمكن تحديد وقت مخصص بالأمر `/time 75` (5 إلى 600 ثانية). يظهر settings أيضًا في قائمة `/` بعد تشغيل النسخة الجديدة. التعديل لأدمن الكروب أو صاحب اللعبة الجارية، وفي الخاص لصاحب المحادثة. الإعداد محفوظ في SQLite لكل كروب/قسم، ويطبق من التلميح القادم وعلى الألعاب الجديدة. لا يعيد ضبط مهلة التلميح المعروض حاليًا. كل التلميحات الأربعة لها نفس المهلة.

لا تحتاج CLUE_SECONDS للتعديل من تيليگرام؛ المتغير يحدد القيمة الافتراضية فقط قبل وجود إعداد محفوظ. لحفظ الوقت والنقاط بعد إعادة النشر استخدم قرصًا دائمًا وDB_PATH. استبدل bot.py وengine.py معًا أو ارفع محتويات هذه الحزمة كاملة، مع الاحتفاظ بقاعدة بياناتك وBOT_TOKEN.
